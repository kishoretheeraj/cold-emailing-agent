## Finding fixed before merge

**P1: submission did not revalidate its lease and approval after browser preparation.**
The submit worker checked the revision before opening the browser. Progress heartbeats were
best-effort and ignored whether their conditional update matched. A worker resuming after lease
recovery, or an application whose document revision changed during filling, could still click
Submit. Lease-guarding the later database write does not prevent that external action.

Added `db.renew_submission_lease`, a conditional heartbeat update requiring the same lease,
submitting status, ready-to-submit stage, non-null approval, and both revision hashes matching
the revision used to prepare the form. `submit()` requires a successful renewal immediately
before the final click. A zero-row result or database error stops before clicking; its existing
conditional release cannot overwrite a different worker's lease. Renewing the heartbeat also
causes concurrent stale recovery to recheck and refuse an obsolete cutoff.

Three regression tests failed on the original code and pass with the fix. Additional stateful
query tests cover recovered/replaced leases, changed status/stage/revision, removed approval,
and a database outage. This check does not make the external website and database transactional
or replace the planned immutable document snapshots.
